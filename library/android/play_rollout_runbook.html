3 · Step-by-step rollout

0Pre-flight (before touching Console)

  • Signed AAB verified (id / vc82 / key / assets) — done
  • Store icon + feature graphic + TV banner generated (Downloads) — done
  • Founder eyeball: new icon + banner on the real TV launcher (clean uninstall→install of the release build — the launcher caches banners; only a clean install refreshes)
  • Capture 2–4 TV screenshots when the TV is reachable: channel grid, player + channel-bug overlay, login. Unaltered 1280×720 screencaps are spec-valid
  • Decide the guest-persistence question (flagged below) — if changing, it must go into THIS build, not after review

1Play Console → App content (do this BEFORE uploading the build)

  • Privacy policy: paste https://wiom-using-ai.github.io/wiom-tv-legal/
  • Data safety: enter the 6 rows from audit/data_safety_declaration.md, encryption=Yes, deletion=Yes
  • Content rating: run IARC questionnaire per audit/content_rating_questionnaire.md → expect Teen/12+
  • App access: paste the guest-access text from section 1C
  • Ads: No · Target audience: 13+ (matches rating; never select under-13 — triggers Families policy)
  • News app declaration: No (we are an entertainment/live-TV app, not a news publisher)

2Store listing refresh (Store presence → Main store listing)

  • Replace app icon with wiom_tv_playstore_icon_512.png
  • Replace feature graphic with wiom_tv_feature_graphic_1024x500.png
  • Upload TV banner wiom_tv_tv_banner_1280x720.png (Android TV section)
  • Upload the new TV screenshots; delete any old-app screenshots
  • Re-read title/short/full description: no superlatives or ranking claims, functionality must match vc82 (guest viewing, 258 channels, OTP login)

3Upload & internal validation

  • Release → Internal testing → create release → upload wiom-tv-vc82-13.1.1.aab
  • Release notes (en-IN + hi-IN): brief, factual — “New launcher artwork, remote-control improvements, updated channel lineup”
  • On a TV with the LIVE app installed from Play: join internal testing, confirm it updates over the live app (no uninstall) and boots to playback
  • Check the Pre-launch report (Console runs it on real TV devices): fix anything red before promoting; screenshots it takes are a preview of what the reviewer sees
  • Console warnings panel: the native-symbols warning will remain — expected/cosmetic (prebuilt stripped AndroidX libs)

4Kill the rejected release & submit

  • On EVERY track that carries vc81: edit release → remove vc81 (“Not included”) so review evaluates only vc82
  • Promote vc82 → Production → staged rollout 10%
  • Submit for review. Do NOT stack other Console changes while in review (each edit can re-trigger review)

5Post-submit monitoring

  • Review typically 1–7 days (longer after a prior rejection). Watch Console Inbox + the policy-status page
  • Day 1 after approval: Crashlytics (crash-free %), CleverTap app_open/ttff/play_error, Play Vitals (ANR <0.47%, crash <1.09% thresholds)
  • Ramp 10% → 25% → 50% → 100% over ~a week if vitals hold; halt rollout instantly from Console if not
  • Keep the gist kill-switch + force-update gate ready — they are the fleet levers if a channel or build misbehaves
  • If rejected again: the notice names the exact policy — reply via the appeal link with the fix; do not resubmit blind

4 · Flagged — decide or accept before submitting

Guest login wall on every reopen. Guest is deliberately not persisted; double-BACK now makes exits routine, so the reviewer will meet the login screen repeatedly. Compliant (guest path + App-access instructions), but if the founder wants it fixed, it must ship IN vc82’s replacement — deciding after approval means another review.
TV-PC: OK-button opens the grid, not pause. Deliberate cable-surf UX; media keys satisfy pause. Small residual review risk — accepted, with a ready remap plan if flagged.
Screenshots are the last hard blocker. TV-G4 requires at least one unaltered current-app TV screenshot, and the live listing still shows the old app. Don’t submit without them. Avoid raw broadcast frames (identifiable people / third-party content in marketing assets).
Content licensing (standing, founder-accepted). 257/258 channels rights-unverified. This review pass is about TV quality, but Google can act on IP at any time — the kill-switch is the mitigation. Unchanged from vc81.
Passed-in-vc81 items (evidence-based low risk): location permission at first boot, Hindi-first UI, OTP login flow, 258-channel catalog — all were in the build Google reviewed; only the icon came back. Changing them now is optional, not required.
