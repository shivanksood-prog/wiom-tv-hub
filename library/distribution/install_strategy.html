Wiom TV · Distribution Strategy

The most frictionless way to install Wiom TV on 1.5 lakh households

Customers' own Google-certified Android TVs · all on Wiom's network · non-tech audience. The answer isn't one magic flow — it's a tiered funnel built around the one install mechanic that's real, free, and ToS-clean.

5 strategies generated 14 AI agents · web-verified Adversarially stress-tested

Bottom line up front

All five independent strategies converged on the same real mechanic: Google's cross-device remote install — push the app from the phone's Play Store onto a same-account Android TV, over the air, with nothing typed on the TV. That's the right spine. But it has one fatal precondition that reshapes the whole plan.

The insight that changes everything

⚠ The binding constraint

The remote install only works when the phone and the TV share one Google account — and Wiom is structurally blind to that. You own router-MAC ↔ mobile, not the Gmail signed into the TV. In non-tech Indian homes the TV is routinely set up on an installer's, a relative's, or no account at all. Realistic same-account rate: ~25–40%, and unobservable in advance.

So the "one-tap magic install" is a thin top slice, not the whole plan. The honest answer is a tiered funnel. Do not let anyone ship this as "the network silently installs it" — it cannot, legally or technically.

The recommended primary path

Network-timed phone remote install

Every step is on the phone. Zero taps on the TV remote. Fires only when Wiom's router sees the TV online.

1
Tap the in-app card / push Tap 1 "Install Wiom TV on your TV" → deep-links straight to the Play listing on the phone. Kills the baseline's sign-in + search + scroll.
2
Tap the small down-arrow next to Install Tap 2 Opens the device picker. This tiny, unlabeled arrow is the #1 fall-off point — guide it with an animated overlay Wiom draws on top. There is no URL param to pre-select the TV (verified), so this tap is irreducible and must be shown, not explained in words.
3
Tick your TV in the list Tap 3 Only same-account, active-in-30-days devices appear here.
4
Tap Install Tap 4 App downloads over-the-air onto the TV by itself. Nothing more on the phone.
5
Walk to the TV, open the tile once TV Forced launch is not allowed — this last step is irreducible. Soften it with a "Your Wiom TV is ready — open it now" push fired off the on-network first-boot ping.
✓ Realistic floor: 4 phone taps + 1 TV-open — no typing, no Google sign-in, no search, no remote, no field visit (for the account-matched segment).

What Wiom must build

  1. Publish a leanback / TV build in the SAME Play listingCritical
    The TV only appears in the phone's device picker if the listing has a TV build (touchscreen required=false + LEANBACK_LAUNCHER). A phone-only listing will never show the TV. Nothing else works without this.
  2. One-tap deep-link CTA in the Flutter appHigh
    https://play.google.com/store/apps/details?id=<pkg> (with market:// variant). Removes the baseline's sign-in + search + scroll.
  3. Animated micro-coach overlayCritical
    For the down-arrow → tick → Install sequence. Highest-leverage UX build — these taps are mandatory and must be shown visually, not described.
  4. Network detection + suppression layer
    Fingerprint TVs on the router (MAC-OUI + SSDP/mDNS/Cast), join to router-MAC↔mobile, and actively suppress nudges to Fire TV / Tizen / webOS / non-certified boxes that can't install from Google Play. Use this to time the nudge, not promise eligibility.
  5. Router-MAC auto-auth on the TV app
    So there's zero login wall on the TV after install — removes the biggest post-install drop the production login-wall app suffers.
  6. First-boot heartbeat → free server-side verification
    Keyed to TV router-MAC (CleverTap/Crashlytics already live). Confirms success, suppresses re-nudges, re-targets only misses.
  7. Wrong-device-install detectorHigh
    If the binary launches on the phone (no TV-side MAC ping), fire "Installed on your phone — let's get it onto your TV." This false-completion trap is worse than baseline if unhandled.
  8. Graceful fallback routing
    Drop to Tiers 2–4 the moment the picker path fails or the heartbeat doesn't arrive.

The tiered funnel — the actual plan

Treat 1.5L as an upper bound — real Google-certified-Android-TV penetration must be measured, not assumed. Harvest the free core before spending a rupee.

What's NOT allowed — stop anyone chasing these

✕
Silent LAN/DNS APK push onto the TV. Forbidden. Android sandbox + Play ToS require explicit per-install consent. Controlling DNS/router does not grant install rights.
✕
Captive-portal install injection. The portal WebView is scoped to network sign-in only — it can show a landing page / QR, nothing more.
✕
A programmatic "install API." There is no public Play install API. Remote install lives only inside the official Play app/web UI. The device-picker tap is the consent gate.
✕
Pre-ticking the TV / a URL param that pre-selects it. Doesn't exist (verified). The deep link opens the listing only — the 3 picker taps are irreducible.
✕
Forced app launch on the TV. Not permitted — the household must open it once themselves.
✕
Zero-touch / MDM / managed-Play provisioning. Applies only to company-owned, factory-reset, enrolled devices. These are customers' own, already-set-up TVs. Not applicable — don't let anyone pitch "QR provisioning."
✕
A QR scanned by the TV. TVs have no camera. Any QR is scanned by the phone and just re-enters the same account-gated phone flow.

Top risks

1
Same-account rate is unknown and unobservableIt sizes the entire free warm core. Realistic guess 25–40% — but it's a guess until piloted.
2
Down-arrow discoverability → false completionNon-tech users miss the dropdown, install on the phone, see "success," and disengage. Worse than baseline. Mitigated only by the overlay + wrong-device detector.
3
Detection pollutionMAC/SSDP flags hardware, not a Play-capable OS. Fire TV / Tizen / webOS / non-certified boxes dead-end. Must suppress, not just target.
4
Gemini replacing Google Assistant on Google TV (through Mar 2026)The agent may answer "Wiom TV" with a spoken reply/search instead of the Play install page — threatening the voice-install fallback. Re-test before relying on it.
5
Field-channel cost & coverageIf leaned on to clear the standing base, it violates the minimise-human-intervention goal and inflates blended cost.

The one thing to pilot first

Measure the warm core before you size the campaign

On a few thousand warm households (Wiom app present, Android-TV-like MAC online), fire the deep-link nudge and instrument exactly three numbers:

1
% whose deep link surfaces a TV in the pickerThe only live, real-world proxy for same-account match — nothing else can give you this number.
2
% who complete the installConfirmed by TV first-boot router-MAC heartbeat.
3
Dropdown-completion vs phone-mis-installValidates the animated overlay actually works.

This single experiment converts the plan's biggest unknown — how big is the free warm core vs how much you must pay to assist the tail — from a guess into a measured number. Do not size the 1.5L campaign until it returns.
